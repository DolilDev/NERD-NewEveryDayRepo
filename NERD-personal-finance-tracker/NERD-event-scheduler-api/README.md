# Event Scheduler API with Notification System

A small RESTful API for managing calendar-style **events**, each of which can fire
a **notification** a configurable number of minutes before it starts. Notifications
are delivered through a swappable transport: a **console** transport by default, or
an **email** transport (via [Nodemailer](https://nodemailer.com/) + an
[Ethereal](https://ethereal.email/) test account) when an event carries an email
address.

Storage is in-memory (a plain array), so the project is dependency-free to run and
easy to reason about — at the cost of not surviving a restart (see
[Known limitations](#known-limitations)).

## Tech stack

| Concern         | Choice                                    |
| --------------- | ----------------------------------------- |
| Runtime         | Node.js (LTS)                             |
| HTTP framework  | Express 5                                 |
| Email           | Nodemailer + Ethereal test account        |
| Scheduling      | `setTimeout` (in-process)                 |
| Tests           | Jest + Supertest                          |
| Container       | Docker + Docker Compose (`node:lts-alpine`) |

## Architecture

The code is organised in clear layers so each concern is isolated and testable:

```
src/
  app.js                      Express app factory (wires routes + error handling)
  server.js                   Entry point (binds the port)
  routes/                     HTTP routing
    healthRoutes.js
    eventRoutes.js
  controllers/                Request/response handling
    eventController.js
  services/                   Business logic
    eventService.js           CRUD + notification orchestration
    notificationService.js    setTimeout scheduling with an injectable transport
  store/                      Persistence
    eventStore.js             In-memory array store
  validation/
    eventValidation.js        Input validation (separate module)
  transports/                 Notification delivery
    consoleTransport.js       Default transport
    emailTransport.js         Ethereal email transport
  middleware/
    errorHandler.js           Centralized error + 404 handling
  errors/
    ApiError.js               Operational error carrying an HTTP status
```

Request flow: **routes → controllers → services → store**, with the
`notificationService` driven by the service layer.

## Getting started (local)

Requirements: Node.js LTS (18+) and npm.

```bash
npm install
npm start            # starts on http://localhost:3000
# or, with auto-reload during development:
npm run dev
```

Set a custom port with the `PORT` environment variable:

```bash
PORT=4000 npm start
```

Health check:

```bash
curl http://localhost:3000/health
# { "status": "ok", "uptime": 1.23, "timestamp": "..." }
```

## Running with Docker

```bash
docker compose up --build
```

The API is then available on `http://localhost:3000`. Stop it with
`docker compose down`. The image is based on `node:lts-alpine` and installs only
production dependencies.

## Event model

| Field              | Type             | Required | Notes                                                |
| ------------------ | ---------------- | -------- | ---------------------------------------------------- |
| `id`               | string (UUID)    | —        | Generated by the server                              |
| `title`            | string           | yes      | Non-empty                                            |
| `description`      | string           | no       | Defaults to `""`                                     |
| `date`             | string (ISO 8601)| yes      | When the event starts                                |
| `notificationTime` | number           | yes      | Minutes before `date` to send the notification (>=0) |
| `email`            | string \| null   | no       | If present, the notification is sent via email       |
| `createdAt`        | string (ISO 8601)| —        | Set on creation                                      |
| `updatedAt`        | string (ISO 8601)| —        | Set on update                                        |

## API reference

Base URL: `http://localhost:3000`

All errors share a consistent JSON envelope:

```json
{ "error": { "message": "…", "details": ["…"] } }
```

`details` is included only for validation errors. Status codes: **400** (validation
/ malformed JSON), **404** (not found), **500** (unexpected server error).

### `GET /health`

Liveness probe.

```bash
curl http://localhost:3000/health
```

### `POST /events`

Create an event. Returns **201** with the created event.

```bash
curl -X POST http://localhost:3000/events \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Team Standup",
    "description": "Daily sync",
    "date": "2030-01-01T10:00:00Z",
    "notificationTime": 15,
    "email": "me@example.com"
  }'
```

Response:

```json
{
  "id": "9c8b7a6d-…",
  "createdAt": "2026-06-19T10:00:00.000Z",
  "title": "Team Standup",
  "description": "Daily sync",
  "date": "2030-01-01T10:00:00Z",
  "notificationTime": 15,
  "email": "me@example.com"
}
```

Validation error (**400**):

```json
{
  "error": {
    "message": "Validation failed",
    "details": ["title is required and must be a non-empty string"]
  }
}
```

### `GET /events`

List all events. Returns **200** with an array.

```bash
curl http://localhost:3000/events
```

### `GET /events/:id`

Fetch a single event. **200** with the event, or **404** if it does not exist.

```bash
curl http://localhost:3000/events/9c8b7a6d-…
```

### `PUT /events/:id`

Replace an existing event (same body as `POST`). **200** with the updated event,
**400** on invalid input, or **404** if it does not exist. The notification is
rescheduled to match the new values.

```bash
curl -X PUT http://localhost:3000/events/9c8b7a6d-… \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Team Standup (moved)",
    "date": "2030-01-01T11:00:00Z",
    "notificationTime": 30
  }'
```

### `DELETE /events/:id`

Delete an event and cancel its pending notification. Returns **204** (no body),
or **404** if it does not exist.

```bash
curl -X DELETE http://localhost:3000/events/9c8b7a6d-…
```

## Notifications

When an event is created or updated, a notification is scheduled with
`setTimeout` to fire `notificationTime` minutes before `date`. Updating an event
reschedules it; deleting an event cancels it. If the notification moment is
already in the past, nothing is scheduled.

- **No `email`** → the **console transport** logs the reminder.
- **With `email`** → the **email transport** sends the reminder through a
  Nodemailer + Ethereal test account.

### Ethereal email + preview URL

The email transport calls `nodemailer.createTestAccount()` on first use to obtain
throwaway SMTP credentials — **no real credentials are stored anywhere**. Ethereal
does not deliver mail; instead each message gets a browser-viewable preview. The
transport logs that link:

```
[notification] Email sent for "Team Standup" -> me@example.com. Preview: https://ethereal.email/message/XXXXXXXX
```

Open the printed **Preview** URL to inspect the rendered email.

## Testing

```bash
npm test          # run the test suite
npm run coverage  # run with a coverage report (enforces >= 80%)
```

Tests use Jest + Supertest. `setTimeout` is driven with Jest fake timers and
Nodemailer is mocked, so the suite makes no network calls. Current coverage is
**100% of statements/functions/lines** and is gated at a minimum of **80%**.

## Known limitations

- **Notifications are in-memory and do not survive a restart**: events live in a
  plain array and pending `setTimeout` timers are lost when the process stops, so
  scheduled notifications are not restored on restart.
- **`setTimeout` maximum delay (~24.8 days)**: Node stores the delay in a signed
  32-bit integer, so delays beyond `2^31 - 1` ms are clamped to that maximum;
  notifications further than ~24.8 days out fire at the clamp boundary rather than
  the exact time.
- Single-process only; in-memory state is not shared across multiple instances.
